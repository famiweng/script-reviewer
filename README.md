## 🎯 设计哲学与解决痛点

在传统的剧本审稿 Prompt 中，将**错别字、空间站位、剧情因果、人物动机、台词潜台词、行业常识与政策审查**全部塞进同一个提示词，会导致大模型出现严重的**注意力稀释（Attention Dilution）**与**长文本中间遗忘（Lost in the Middle）**。

`script-reviewer v2.0` 采用**“三权分立 + 模块化分工 + 状态机追踪”**的工业级设计：
- **物理场记归场记**：遵循中美工业剧本排版标准，严审空间几何、轴线视向、道具全生命周期与动作物理连贯性。
- **叙事因果归因果**：自适应匹配电影/长剧/短剧载体结构，度量各集戏剧压力（1~10），严审查事件链条、信息差闭环、伏笔与钩子。
- **人物心理归心理**：聚焦深层心理创伤（Ghost/Need）、权力位阶（Status）、情感账户收支（Emotional Debt/Credit）、潜台词意图层与四大“Show, Don't Tell”视听化重构。
- **制片合规归制片**：把关政策审查红线、行业垂直真实性、侵权融梗预警与制片预算黑洞。
- **总控大脑出白皮书**：聚合降噪、输出四大台账与增量 Diff 日志、构建双向修改 Diff、支持全景宏观复盘。

## 🛠️ 双向代码级修补引擎 (Forward vs. Backward Patch)

面对跨集矛盾或逻辑悬空，系统不再只是笼统建议，而是直接生成两种代码级剧本修改 Diff：

```markdown
#### 方案 A：前向修补 (Forward Patch · 修改前文第 3 集)
> 适用场景：剧本仍处于大修期，允许改动前文。
```diff
--- 第3集 第5场 (修改前)
+++ 第3集 第5场 (修改后)
 李娜把公文包锁进保险柜。
+李娜从公文包夹层取出一枚黑色U盘，悄悄塞入大衣内衬。
```

#### 方案 B：后向修补 (Backward Patch · 修改当前第 20 集)
> 适用场景：前文已定稿或已拍摄，必须在当前集自圆其说。
```diff
--- 第20集 第12场 (修改前)
-李娜从大衣内衬掏出那枚五年前的U盘。
+李娜：“当年从公文包里拿到的U盘虽毁了，但我早把备份传到了云端。”
```

## 🔄 上下文自适应双模审查机制 (Mode A vs Mode B)

为了兼顾“单场随手抽审”与“多集严密把关”，所有子技能均支持**智能上下文感知与双模态自适应切换**：

```
                              [用户输入剧本内容]
                                      │
                 ┌────────────────────┴────────────────────┐
                 ▼ (检测到有前情/有四大台账/第1集)           ▼ (未检测到台账，抽取片段)
       【Mode A：全局台账绑定模式】                  【Mode B：单场盲审模式】
                 │                                         │
        • 适用：【模式二】多集滚雪球或带大纲模式          • 适用：【模式一】用户随手抽发单场对白/动作
        • 行为：严查跨集连续性、机械降神与长线弧光        • 行为：聚焦当场戏内即时逻辑、对白潜台词
        • 输出：标准 P0/P1/P2 + 资产增量 Diff 日志        • 输出：即时改写示范 + 存疑因果假设清单
```

* **Mode B 的防御性防线**：在单场盲审时，技能**绝不武断把前置未提及的道具/线索判为“机械降神死刑”**，而是出具《存疑前置因果假设清单》，供主创对照确认。

## 🚨 分级审查标准 (P0 / P1 / P2)

| 级别 | 标识 | 定义与标准 | 处理策略 |
| :--- | :--- | :--- | :--- |
| **P0** | **🚨 致命硬伤** | • 触犯政策审查红线（不可过审/违规办案/历史虚无主义）<br>• 主线因果彻底断裂 / 机械降神<br>• 人设严重崩塌 (OOC) / 违背情感账户历史<br>• 阻断拍摄级穿帮（道具凭空瞬移、空间轴线对撞） | **必须修改**<br>附带双向修补 Diff，拍摄或报审前必须清零 |
| **P1** | **⚠️ 重要问题** | • 缺乏过渡的突兀情绪跳变 / 权力位阶失真<br>• 生硬的说明性对白 (Exposition Dumps)<br>• 缺少集尾悬念钩子 (Cliffhanger) 或载体节拍塌陷<br>• 明显的行业专业常识错误 / 同质化烂梗<br>• 场号跳漏 / 修订痕迹遗留空白 / 伤情演变脱节 | **强烈建议修改**<br>提供 Show, Don't Tell 视听示范 |
| **P2** | **💡 打磨建议** | • 潜台词留白与对白高级感提升<br>• 镜头化视听语言转化（小说描写镜头化）<br>• 制片降本增效（场景合并/精简转场）<br>• 格式标点与括号提示语规范排版 | **供主创斟酌**<br>尊重个人风格，锦上添花 |

## ❓ 常见问题与实战技巧 (FAQ)

### Q1：为什么台账中支持 `[LOCKED]` 锁定标记？
> **答**：为了防止模型在增量审核中出现误判或遗忘。编剧人工确认过的关键核心伏笔或人物设定加上 `[LOCKED]` 标记后，后续各轮增量审查将强制以该设定为不可撼动的基准。

### Q2：面对不同题材（如仙侠 vs 刑侦），如何保证专业核查准确？
> **答**：`script-production-domain-expert` 会根据剧本题材自适应切换知识库。审刑侦时严格核查刑事诉讼法与公安规范；审仙侠/科幻时则切换为核查其内在世界观法则自洽性与特效制作预算风险。
